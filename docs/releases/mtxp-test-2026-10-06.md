## Retail startup regression

The 12.1.0.69933 SoundKit table contains 333,900 readable rows. Native DB2
decoding took 3.6 seconds, but building the legacy picker view called addRecord
for every row. Its duplicate-ID scan made this step quadratic and blocked
the UI for minutes without further disk reads.

SoundKit now validates IDs with a hash set, allocates the compatibility table
once, and fills records by position. Column lookup is done once per field.
Other DBC editing and native DB2 saving behavior is unchanged. Stage logs
distinguish source loading, decoding, and editor-view construction.

The standalone test compiles the production DBCFile methods and verifies
333,900 rows, ID ordering and boundaries, zero initialization, string/float
writes, duplicate rejection, invalid layouts, and empty tables (131 ms).

Full rebuilt Noggit startup with the existing Retail project passed the former
stall: SoundKit decoding took 3,719 ms and editor-view construction 4,056 ms.
The map bootstrap and lighting bridge completed, the map selector appeared,
and the application became responsive while loading a selected map's assets.
This verifies the startup fix, not the pending MTXP painting/save/reopen test.
